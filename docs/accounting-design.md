# طرح بخش حساب‌داری (پیاده‌سازی شده - 2026-08-08)

تاریخ توافق: ۱۴۰۵/۰۵/۱۷ (2026-08-08)

## تصمیم‌های نهایی

- سه سطح دید: سوپرادمین (کل پنل) / ادمین سطح ۲ (خودش + فروشنده‌هایش) / فروشنده (فقط خودش)
- پوشش: تراکنش‌های مالی کاربران + حساب ادمین‌ها و فروشنده‌ها + هزینه‌ها و درآمد کلی + گزارش‌گیری و خروجی
- داده‌های قدیمی: در زمان نصب، خریدهای موجود و لاگ‌های اعتبار (AdminBalanceLog) یک‌بار به دفتر کل منتقل می‌شوند (backfill)
- ثبت هزینه: فقط سوپرادمین
- UI: منوی مستقل «حساب‌داری» در سایدبار با تب‌ها: داشبورد / تراکنش‌ها / هزینه‌ها / گزارش

## معماری

### ۱. منابع رویداد مالی (ثبت خودکار در لحظه‌ی وقوع)

- خرید/تمدید از ربات تلگرام (رسید کارت‌به‌کارت تاییدشده یا پرداخت با کیف پول)
- شارژ کیف پول مشتری (رسید تاییدشده)
- ساخت/تمدید سرویس از پنل وب (کسر از اعتبار ادمین/فروشنده به قیمت همکاری)
- شارژ/کسر اعتبار ادمین یا فروشنده (توسط سوپرادمین یا ادمین والد)
- ثبت هزینه‌ی دستی توسط سوپرادمین (سرور، پهنای باند، متفرقه)

### ۲. دفتر کل (Ledger) - جدول واحد

هر رویداد یک رکورد: نوع تراکنش، مبلغ (تومان)، مشتری مربوطه، ادمین/فروشنده مربوطه،
کارت مقصد (در صورت کارت‌به‌کارت)، کد تخفیف اعمال‌شده، تاریخ/ساعت.

### ۳. نماهای نقش‌محور

- سوپرادمین: درآمد کل، تفکیک به ادمین/کارت/بازه، هزینه‌ها، سود خالص
- ادمین سطح ۲: فروش مستقیم خودش + فروش هر فروشنده‌اش، گردش و مانده اعتبار، حساب هر فروشنده
- فروشنده: فروش خودش، حاشیه سود (قیمت فروش خودش − قیمت همکاری)، گردش اعتبار خودش

### ۴. گزارش‌گیری (در محدوده‌ی دید هر نقش)

فیلتر بازه زمانی / ادمین / کارت / نوع تراکنش، نمودار روزانه و ماهانه، خروجی اکسل.
